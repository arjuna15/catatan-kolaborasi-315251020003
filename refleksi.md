# Refleksi Pembelajaran Git dan Version Control

Menggunakan Git sebagai sistem pengontrol versi (*version control system*) memberikan pengalaman yang jauh lebih terstruktur dibandingkan metode konvensional seperti menamai berkas dengan "final_revisi" atau "final_beneran". Hal yang terasa jauh lebih mudah adalah pelacakan riwayat pekerjaan yang runtut dan rapi. Setiap perubahan tercatat secara atomik melalui pesan commit yang jelas, sehingga saya dapat mengetahui alasan suatu perubahan dilakukan serta dapat mengembalikan kondisi berkas ke titik sebelumnya kapan saja tanpa khawatir kehilangan data berharga. Repositori proyek juga tetap bersih tanpa tumpukan salinan berkas duplikat.

Sebaliknya, hal yang terasa cukup menantang pada awalnya adalah memahami konsep *staging area* serta keharusan menjaga disiplin dalam melakukan satu perubahan logis per commit. Mengoperasikan perintah berbasis terminal dan memastikan pesan commit deskriptif membutuhkan ketelitian lebih tinggi daripada sekadar menekan tombol simpan biasa.

Ke depan, satu hal penting yang sangat ingin saya pelajari lebih lanjut adalah manajemen percabangan (*branching*), *pull request*, dan strategi penyelesaian konflik (*merge conflict*) saat berkolaborasi aktif dengan banyak pengembang dalam satu repositori.
